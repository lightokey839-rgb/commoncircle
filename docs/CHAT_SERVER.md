# CommonCircle chat and sign-in server

`server/auth.ts` serves NEP-413 sign-in, the members-only circle chat and the
"ask the circle" loan request cards. It never receives private keys, seed phrases
or invite secrets, never signs a transaction and never moves money.

**Chat is access-controlled, not end-to-end encrypted.** Messages and loan reasons
are off-chain, in the server's database; the operator can read them. Loan terms,
account IDs and passport history are public on-chain.

## How it works

| Part | What it does | Code |
|---|---|---|
| Sign-in | `POST /nonce` stores a one-time challenge (5 min) naming this app's host as recipient; `POST /verify` atomically consumes it, checks the ed25519 NEP-413 signature and that the key is a **full-access key** of the account on testnet, then issues an HS256 session token (12 h, `iss`/`aud` checked). Replays, expired nonces, wrong recipients, tampered messages and forged tokens are refused. | `server/app.ts`, `server/nep413.ts` |
| Membership | Every chat and request call runs the contract's `check_access` on testnet. "Member" answers are reused for 15 s, "not a member" for 5 s, RPC failures never: the server fails closed with a 503 "try again". A revoked passport loses access within 15 s. | `MembershipGate` in `server/chat.ts` |
| Messages | One room per circle; ids are 1, 2, 3… per room, assigned under a row lock, so they become visible in order and polling with `after=` never skips one. `before=` pages older history. 1000 characters max, hidden/direction-changing characters refused, 8 messages per 30 s per account. | `server/chat.ts` |
| Loan requests | Card (amount, days, reason) → offers → borrower picks a lender and signs `create_loan` in their wallet → server links the loan after checking borrower, circle, amount, days and that the lender offered. One loan can be linked to one card only (lock + unique index). | `server/requests.ts` |
| Storage | PostgreSQL in production (shared by any number of processes); JSON files for local development (one process only); memory in tests. Production refuses to start without a database. | `server/store*.ts`, `server/migrations/` |
| Delivery | Polling (every 3 s while the chat is open, 15 s in the background), cursor-based, merged by id, so a refresh or reconnect resumes without duplicates. Not instant real-time delivery. | `web/chat.ts`, `web/app.ts` |

## Run locally

```bash
npm run auth        # development: JSON files in server/.data
npm run test:db     # PostgreSQL tests on a throwaway local database
```

With a local PostgreSQL: `DATABASE_URL=postgres://… npm run auth` (migrations apply on start).

## Host it (Render, free plan)

1. Sign in at https://render.com with GitHub → **New → Blueprint** → repository
   `lightokey839-rgb/commoncircle`, branch `lane/contracts`. Render reads `render.yaml`
   and creates a PostgreSQL database plus the `commoncircle-chat` web service
   (Docker, `deploy/Dockerfile`). `AUTH_JWT_SECRET` is generated by Render.
2. When it is live, open `https://<service>.onrender.com/health`: it must say
   `"store":"postgres","shared":true`.
3. Tell the web app where it is: repository variable `COMMONCIRCLE_AUTH_URL` =
   the service URL, then run the **Deploy CommonCircle testnet demo** workflow.

Other hosts: build `deploy/Dockerfile` and set the variables listed in `.env.example`
(`COMMONCIRCLE_ENV=production`, `DATABASE_URL`, `AUTH_JWT_SECRET`, `APP_ORIGINS`,
`NEAR_AUTH_RECIPIENTS`, `AUTH_TRUST_PROXY=1` behind a proxy).

Free Render services sleep when idle; the first request after a pause can take
about a minute, and the app shows "chat server is waking up / not answering" with
Retry until it answers.
